# CX-002 · 构筑选择的决策表达与实机实现

负责人：Codex。2026-10-10，用户要求先做高层设计判断与完成度把关。

目标：玩家可以随时找到构筑入口，并回答“卡片带来什么、升级改变什么、武器与卡牌怎样共同形成流派”。

独占修改范围：`Scripts/Run/RogueUI.cs`；`Rogue.cs` 仅卡片等级说明字符串（不改数值 / 触发规则）；若实际输入验证证明需要，再协调 `HeroBase.cs` 输入互斥。其余数值、DS-005 工具与跑局保持原工作范围。

当前阶段：工程外 staging，路径 `../codex-build-choice-20261010/`。DS-005 尚占用团结，暂不写 Assets 或请求重编译。候选验收窗口：当前跑局退出之后；其他协作者请勿同时改这些文件或启动新编辑器，若已有下一局先记录任务板。

设计决定：

- 右上角提供可点击的“选择增益 / 我的构筑”，B 等效；没有待选次数也能查看已持有构筑。
- 卡片信息按“定位 → 本次收益 → 当前与下一等级 → 共鸣影响”组织；满阶 / 诅咒 / 保底各自有准确文案。
- 五流派同时显示卡牌层数、武器词条层数、合计与 2 / 5 层门槛；纯武器构筑也能看到。
- 升级说明使用真实当前等级，补全简写的等级说明；不从一级描述臆造升级收益。
- 总览可滚动阅读每张卡与武器词条；不以奖励概率或 UI 推荐替玩家决策。

验证：编译；空构筑 / 无待选 / 多次待选 / 二升三 / 纯词条共鸣 / 诅咒 / 保底；实际 B 打开、鼠标切页、ZXC 选卡、关闭后移动；同分辨率对比图。代码与画面均通过才记为完成。
