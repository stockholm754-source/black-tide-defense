# RUN-001 · 跑局窗口执行清单（等用户许可）

> 准备：DeepSeek（副总工程师）。判定表与回调预案见 `collab/reports/DS-002_report.md` 第 3 节。
> 目标：验证 ExpBase 7.4 + 黑潮王伤害 +25%（两者已入代码，从未跑过局）。

## 跑什么

三路线各一局（顺序建议：稳健 → 激进 → 贪信使），沿用既有跑局方式：

1. 团结编辑器**必须在系统前台**（不在前台 Play 会卡住；computer-use 切过去）。
2. 场景 `Assets/BlackTide/Scenes/BlackTide_Run.unity`，Play。
3. `HeroBase.Autopilot = true; Feel.SetBaseScale(8f);` 自动代打 8 倍速。
4. 路线由 RunDirector 的策略参数选择（稳健发育 / 激进净化 / 贪信使）。
5. 每局结束自动出 CSV（`Captures/runs/run_*.csv` + `_events.csv`），记下三局的**时间戳前缀**。

## 功耗红线（宿舍）

- 一局实际约 3–5 分钟；**每局之间停一下**观察机器状态；
- 不连续跑、不挂机；用户说停立刻停；
- 这是跑局窗口，用户已同意才开——本次窗口外不开 Play。

## 跑完怎么办（DS-003 管线）

```powershell
python collab/tools/run_report.py Captures/runs --files <局1.csv> <局2.csv> <局3.csv> --write collab/reports/RUN-001_result.md
```

管线自动出：3/7/10.5/14min 检查点、入口等级、决战时长、倒地/团灭、最低平均血量、PASS/FAIL 与不达标项。

## 额外观察项（写进 RUN-001_result.md）

- 引雷/惊雷/嗜战/余韵等新词条的触发表现（若 KB-006 计数已加则读事件，否则目测记录）；
- 贪信使路线的「信使跳跃」前后等级；
- 是否出现倒地→救援、共鸣护盾/团队复活是否被用到；
- 强制终局是否出现（8.8 窗口实测 0 次）；
- 帧率观感（终局特效密度下有没有明显掉帧）。

## 判定（按 DS-002 §3）

- 三局全胜（或两胜一接近团灭）、等级落区间、**有倒地/复活但无团灭** → 通过，数值定稿。
- 不达标 → 按 DS-002 §3 的回调预案：7.4→8.0 / SovereignDmg→1.4 / 激进路线差异化，三选一并说明理由。
