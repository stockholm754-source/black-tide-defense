# KB-007 实现点位建议（DeepSeek，供总工 Codex 定稿）

> 证据链见 `reports/RUN-001_analysis.md`：7.4 下贪信使局 5.9 分钟全队 4 级进信使 → 8.3/9.9 分钟两次团灭 → 侵蚀 +5%/+10% 螺旋 → 13.9 分钟侵蚀满 → 强制终局 7 级 → 负、团灭 3。

## 方案 A（推荐）：信使等级前置

`RouteScore` 是静态纯函数，直接加等级门即可（一行 + 注释）：

```csharp
case Strategy.贪信使:
    // KB-007：7.4 经验下队伍 4–5 级冲信使会被怒涛×2 的 Boss 反复团灭（RUN-001 实测），
    // 等级够了再优先信使（不够时先清低级节点发育）
    if (def.type == NodeType.Messenger && m > 4f && Growth.TeamFracLevel() >= 6f) s -= 220f;
    break;
```

- 阈值建议 **6 级**（8.8 时代贪信使自然进信使约 7 级；7.4 下 6 级进 = 保留一点"贪"的风险，但躲开 4 级送死）。若 RUN-002 仍团灭，提到 6.5 或与方案 B 组合。
- `Growth.TeamFracLevel()` 实时可取（Growth.cs:74），RouteStep 每次选点都调用 RouteScore，无性能问题。

## 方案 B（备选/组合）：路线经验补偿

- 只补偿贪信使路线：在 RunDirector 里给贪信使路线加经验系数（如 ×1.15，作用于 Growth 相关结算），或 RunSim 用 `cfg.messengerExp`（RunSim.cs:38）先扫系数再定。
- 更温和的变体：低等级打信使时动态难度（`TeamFracLevel() < 6.5` 时信使 BossHp ×0.85），改动点 :427-428。

## 边界（不要动的）

- 全局 `Growth.ExpBase = 7.4` 保持不变（三条路线 3/7min 检查点已贴目标）；
- `FinaleReady` 的 8.5 门槛不变；
- 稳健/激进的信使加分（:830/:834）不变。

## 验收（RUN-002 贪信使局）

- 信使战首次进场等级 ≥ 6（事件流里 `engage,X1` 前最后一条 levelup ≥ 6）；
- 10.5min 等级 ∈ [5.5, 6.8]、入口等级 ∈ [8.2, 9.0]、决战 ∈ [150, 260]s、团灭 ≤ 1；
- 无"4–5 级进信使→团灭→侵蚀螺旋"的事件序列。
