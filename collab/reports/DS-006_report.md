## 优先问题（按对真实体验的影响排序）

### F1 · P1 · 选卡面板打开期间玩家完全无法自卫
- 位置：HeroBase.cs:218（`if (ShopUI.IsOpen || RogueUI.IsOpen) { moveIn = Vector3.zero; attackHeld = false; return; }`）+ RogueUI.cs:74 面板打开不暂停游戏。
- 触发：开局拿到待选增益 → 按 B → 面板全屏遮罩（RogueUI.cs:42-43）→ 此时玩家角色站立不动、**移动/闪避/攻击输入全部被提前返回吞掉**（bufDodge 也不写入），但敌人与预警照常行动。
- 玩家后果：读卡时被杂兵围殴只能挨打；开局节点经常"清怪途中解锁增益"，残怪在场概率高。被打到倒地面板才自动关（RogueUI.cs:77）。
- 建议修法（二选一）：**A.** 玩家受击或被预警罩住时自动关闭面板（`h.dmg.onHit` 里关 + AttackTell 威胁命中判定时关）；**B.** 面板打开时允许闪避键透传（ReadPlayerInput 提前返回前处理 dodge 输入）。A 更省心，推荐。

### F2 · P1 · X 键双义：想切武器会误选卡
- 位置：HUD.cs:307（武器栏标注"X / 滚轮 切换"）vs RogueUI.cs:45、106（选卡面板标注"Z / X / C 选择"，X=第 2 张）。
- 触发：有待选增益时按 B 打开面板（RogueUI.cs:71-75），此时 X 被 RogueUI 独占选卡（ReadPlayerInput 提前返回，武器切换被阻断）。
- 玩家后果：玩家习惯性按 X 想切武器 → 直接选中第 2 张卡且**不可撤销**。X 是 HUD 常驻标注的高频键，误伤概率不低。
- 建议修法：选卡键改为 **1 / 2 / 3**（与接力 1/2、道具 3–6 的语义一致），X 永远保留武器切换；或面板内点击为主、键盘仅 1/2/3。

### F3 · P2 · Tab 换人时商店面板货架错位
- 位置：SliceGame.cs:81（Tab 无条件 SwitchControl，无 UI 打开检查）vs ShopUI.cs:125（货架只在 Open 时按 `o.forHero != Combat.player.Id` 过滤一次）。
- 触发：开商店 → 按 Tab 换人 → 货架仍显示为旧角色过滤的武器；且 Economy.CanBuy 对武器**不校验 forHero**（Economy.cs:166-168），新角色能直接买下"给别人的武器"（规则上任何角色可用任何种类，所以不是规则 bug，但违背"只显示自己能用的武器"的 UI 意图）。
- 玩家后果：看到不属于自己角色的武器混在货架里、可能误买。
- 建议修法：ShopUI.Update 检测 `Combat.player.Id` 变化 → 重新 `Open(shopNode)`（或直接关面板）。RogueUI 无此问题（换人后 pending 不符会自动关，RogueUI.cs:77）。

### F4 · P2 · 「按推荐补货」无价格预告
- 位置：ShopUI.cs:75、177-183（AutoBuyPlayer 直调 Economy.AutoBuy，AI 规则一口气买）。
- 触发：点一次按钮，AutoBuy 按 AI 清单（Economy.cs:222-256）购买：保 2 个治疗、买得起的最高星武器（5★ 也可能）、愿望清单道具、团队盾——**可能一次扣掉数百贝币且无逐项确认**（明细只进事件日志）。
- 玩家后果：文案"按推荐补货"让人以为是少量补充，实际可能大额消费。
- 建议修法：按钮旁显示合计预估价（先按 AutoBuy 逻辑试算）；或改为"推荐清单"逐项点击购买。

### F5 · P2 · 选卡面板不响应 Esc（与商店不一致）
- 位置：RogueUI.cs:63-75（只认 B 开关）；ShopUI.cs:112（支持 Esc）。
- 触发：玩家习惯 Esc 关商店，打开选卡面板按 Esc 无反应。
- 建议修法：RogueUI 增加 `Input.GetKeyDown(KeyCode.Escape)` 关闭（一行）。

## 已排除项（依据）

1. **选卡面板打开时 X 不会切武器**：HeroBase.cs:218 提前返回阻断 SwitchWeapon（HeroBase.cs:236）→ 互斥成立（F2 的"误选卡"另一半）。
2. **自动代打与选卡无死锁**：B 在 Autopilot 下禁用（RogueUI.cs:71）、提示隐藏（:69），pending 由 Rogue.Tick:174-175 AutoPick 消耗 → 自动代打不会被待选增益卡住。
3. **面板关闭路径齐全**：pending≤0 关（RogueUI.cs:77）、倒地关（:77）、B 再按关（:73）；商店 Esc/离开商人/倒地关（ShopUI.cs:112）；F2 重开=场景重载，UI 随场景销毁无残留（SliceGame.cs:84）。
4. **商店失败原因齐全**：售罄/贝币不足/本局已限购/团队格已占用/快捷栏已满 五种（Economy.cs:161-181），行内红字显示（ShopUI.cs:154）。
5. **团队道具 AA 摊分一致**：UI 显示"每人 {价/3}"（ShopUI.cs:150）与 Buy 的摊分实现（Economy.cs:196-203）一致。
6. **待选增益可发现性**：右上常驻"团队击杀计数 + 下一次门槛 + B 选择增益(n)"黄字（RogueUI.cs:69），位置在小地图下方，与 Boss 条/玩家条无重叠（静态布局可证）。
7. **选卡信息表达完整**：流派/稀有度/升级/专属/团队标签、共鸣进度与"触发共鸣Ⅱ"预告、诅咒红字警示、底部构筑一览（RogueUI.cs:78-104）齐全。

## 功能边界说明（对应任务书第 7 条）

- 全库代码与脚本 grep「赐福」**0 命中**：赐福点不是已实现功能的 bug，而是**尚未形成规则的缺失功能**（HANDOFF 顶部已记录"赐福点是待形成具体规则的缺失功能"）。
- 现行机制 = 团队击杀计数过阈值 → 每人一次三选一（B），升级 = 选到已有卡（最高 3 级）。这与"自动升级"的玩家表述对应的就是这个三选一体系，**没有独立的自动升级系统**。规则由总工补齐前，不新增玩法。
