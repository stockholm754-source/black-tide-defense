## 开发顺序与验收

| 批次 | 开发内容 | 完成标准 |
|---|---|---|
| 1：可理解的开局与规则一致性 | 修共振 / 余韵适用范围；核查 20 条词条接线；肉鸽入口与待选提示；商人靠近、对话入口、购物、反馈与退出；第一条路线的目标引导、遮挡和尺度 | 从新局用实际输入完成选卡、移动到商人、交易、返回战斗；文本说明与战斗读数一致；没有误触攻击 / 切武器或焦点残留；实际机位前后图可比较 |
| 2：战斗表现与场景品质 | 优先闪电、护盾、风场与治疗的可辨识反馈；普攻 / 技能 / 大招强度分层；珊瑚与建筑遮挡处理；三圈区域材质、光照与地标；构筑触发反馈 | 代表技能各有启动、命中、持续、消散实录；红橙危险预警可辨；队友与敌人、治疗与伤害不混淆；主要路线不被大型道具挡住角色 |
| 3：完整一局与性能 | 接收 DeepSeek 跑局结果；优先复现卡死、死亡 / 救援、重开、商店 / 拾取边界；处理实测帧时间与分配热点；补结算的信息解释 | 三种路线有明确代码版本与数据，成功和失败路径均可退出 / 重开；必要性能样本包含分辨率、敌人数、GPU 渲染状态、帧时间，不能用 headless 代替视觉性能 |

地图品质在每批都验收，先改善开局代表路线，再将成立的规则推广到全图。按问题改有影响的代码，不以大重构作为前置条件。

## 赐福 / 升级点

这是用户明确关注、当前缺失的体验项。现有经验升级是自动的，增益选择来自击杀积分；赐福点必须先明确与这两者的关系。候选定位是休整与构筑整理的场景入口。回血、刷新敌人、武器升级或新增消耗会改变整局规则，先形成一份具体方案与影响说明，重大取舍交用户拍板，避免实现另一套互相冲突的成长系统。当前不把候选规则记为既定设计。

## 协作与改动边界

- **Codex**：优先级、规则决策、核心玩法与 UI 接线、shader / 场景品质、合并与实机验收，对最终可玩结果负责。
- **DeepSeek**：继续 DS-005；之后优先做 DS-006 交互 / 表达审查，负责数值复算、边界用例、独立验证与性能证据。报告是审查输入，发现要用当前代码复核。
- **WorkBuddy / Claude**：可以领取边界明确的地图布景、素材整理、独立功能任务。旧未开工 KB 项进入 Codex 排期；尚未有新任务的接单回执，不视为已经开工。
- 单一任务板 `collab/TASKBOARD.md`。任务写明目标、文件范围、验收、状态与基准版本；共享场景、材质、核心脚本和 Unity 进程同一时段只有一个写入方。集成前核对文件变化，避免覆盖同伴修改。
- 状态分别写“计划 / 已编码 / 已编译 / 实机通过”。直接调用按钮事件只证明回调，真实键鼠输入和完整玩家路径另验。
- 每批给用户可玩的改动、实际画面对比、少量明确的剩余问题；规则和文档及时修正，但报告本身不算游戏改进。

- 规则：`Scripts/Run/WeaponAffix.cs`、`Scripts/HeroBase.cs` 的伤害来源，`Design/echo_weapon_affix.md`；按实际命中来源建立正 / 反用例。

- 场景：`Scripts/Run/MapBuilder.cs`、相机与遮挡代码、现有地图素材；先记录现状机位再改。
- 验证：只读代码与 DeepSeek 结果 → 合并一批修改 → 编译 / Console → 代表交互的真实输入 → 同机位战斗与地图截图 → 保存证据并退出测试。
- 失败预算：同一现象连续两次失败后停止重复尝试，检查当前程序集、实际场景、组件与输入焦点，再改验证路径；不反复重启编辑器碰运气。
